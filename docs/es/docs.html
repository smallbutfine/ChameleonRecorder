Archivos de Configuración

channels.json

Ubicado en /home/recorder/bin/channels.json. Almacena ajustes de armado por dispositivo y por canal para el control remoto web.

Formato

{
  "devices": {
    "system": true,
    "USB_2": false
  },
  "ports": {
    "system:capture_1": true,
    "system:capture_2": false,
    "USB_2:capture_1": true
  }
}
ClaveTipoDescripción
devicesObjetoMapa de nombre de dispositivo a booleano (true = habilitado, false = deshabilitado)
portsObjetoMapa de nombre de puerto JACK a booleano (true = armado, false = desarmado)
Nota: Si un dispositivo o puerto no está listado en la config, por defecto es true (habilitado/armado).

Cómo Funciona el Control Remoto Web

El control remoto web es un servidor HTTP de Python (web_remote.py) que corre en el puerto 8080. Sirve una interfaz HTML de una sola página y proporciona endpoints tipo REST para el control.

Servidor HTTP

Construido sobre http.server.ThreadingHTTPServer de Python. Escucha en 0.0.0.0:8080.

Endpoints

EndpointMétodoDescripción
/GETSirve la interfaz HTML del control remoto web
/statusGETDevuelve JSON: estado de grabación, JACK listo, nombre del dispositivo
/channelsGETDevuelve JSON: puertos de captura JACK disponibles agrupados por dispositivo, más la config actual
/channelsPOSTGuarda la config de armado de canal/dispositivo en channels.json
/levelsGETDevuelve JSON: niveles de pico en vivo (dBFS) para todos los puertos de captura
/filesGETDevuelve JSON: lista de archivos WAV en /media/usb0/ con tamaños
/download/<filename>GETDescarga archivo WAV individual
/download-allGETDescarga todos los WAVs como un archivo ZIP con marca de tiempo
/recPOSTInicia grabación (ejecuta el script rec)
/stopPOSTDetiene grabación (envía SIGTERM a jack_capture)
/del_lastPOSTBorra la grabación más reciente
/rescanPOSTRe-escanea dispositivos de audio USB (ejecuta start_jack)
/delete/<filename>POSTBorra archivo WAV individual

Cómo se Configura JACK

JACK (Jack Audio Connection Kit) es el servidor de audio que gestiona toda la E/S de audio. ChameleonRecorder lo configura automáticamente vía start_jack.

Configuración

ParámetroValorDescripción
Frecuencia de muestreo48000 Hz (alternativa: 44100 Hz)Se prefiere 48 kHz; si falla, se prueba 44.1 kHz
Tamaño de búfer (periodo)2048 framesBalancea latencia vs. estabilidad
Periodos (nperiods)3Número de búfers
DriveralsaUsa ALSA para comunicación con la interfaz de audio USB

Selección del dispositivo maestro

Al arrancar, start_jack escanea todas las tarjetas de audio USB vía /proc/asound/cards y las ordena por número de canales de captura (descendente). La tarjeta con más canales se convierte en el maestro JACK. Las interfaces adicionales se vinculan vía alsa_in.

Setup multi-dispositivo

# Servidor JACK primario (interfaz más grande)
jackd -dalsa -dhw:1 -r48000 -p2048 -n3

# Interfaces adicionales vía alsa_in
alsa_in -j "USB_2" -dhw:2 -r48000 -p2048 -n3

Cómo Funciona la Detección de Sync de Reloj ADAT

Para interfaces Behringer UMC1820, ChameleonRecorder detecta automáticamente señales de reloj ADAT válidas y cambia a sync de reloj externo.

Proceso de detección

  1. start_jack comprueba si la tarjeta tiene el control UMC1820 Clock Selector Clock Source (vía amixer)
  2. Si se encuentra, lee el control Optical In ADAT/SMUX Validity
  3. Si el valor es on (señal ADAT válida presente), establece la fuente de reloj en 2 (ADAT externo)
  4. Si el valor no es on (sin señal válida), establece la fuente de reloj en 0 (interno)

Comandos usados

# Comprobar si UMC1820 está presente
amixer -c 1 controls | grep "UMC1820 Clock Selector Clock Source"

# Leer validez ADAT
amixer -c 1 cget name='Optical In ADAT/SMUX Validity'

# Establecer fuente de reloj a ADAT externo
amixer -c 1 cset name='UMC1820 Clock Selector Clock Source' 2

# Establecer fuente de reloj a interno
amixer -c 1 cset name='UMC1820 Clock Selector Clock Source' 0
Nota: Esta detección corre automáticamente al arrancar y al pulsar Re-Scan USB Audio Device en el control remoto web.

Cómo Funciona el Hotspot de Respaldo

Si no se encuentra ninguna red Wi-Fi conocida en los 25 segundos posteriores al arranque, ChameleonRecorder crea automáticamente un punto de acceso Wi-Fi.

Proceso

  1. Un servicio systemd (wifi-fallback.service) ejecuta /usr/local/bin/wifi-fallback.sh al arrancar
  2. El script espera 25 segundos para una conexión Wi-Fi
  3. Si wlan0 no tiene dirección IP (no conectado), crea un hotspot
  4. El SSID del hotspot es ChameleonRecorder con contraseña chameleon123
  5. El control remoto web es accesible en http://10.42.0.1:8080

Configuración

# wifi-fallback.sh (simplificado)
sleep 25
if ! ip -4 addr show wlan0 | grep -q "inet "; then
    nmcli device wifi hotspot ifname wlan0 \
        con-name ChameleonHotspot \
        ssid "ChameleonRecorder" \
        password "chameleon123"
fi
Consejo: Si la Pi está conectada a una red Wi-Fi conocida, el hotspot NO se activará. Esto es por diseño — la Pi prefiere tu Wi-Fi de casa/estudio.

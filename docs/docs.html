Configuration Files

channels.json

Located at /home/recorder/bin/channels.json. Stores per-device and per-channel arming settings for the web remote.

Format

{
  "devices": {
    "system": true,
    "USB_2": false
  },
  "ports": {
    "system:capture_1": true,
    "system:capture_2": false,
    "USB_2:capture_1": true
  }
}
KeyTypeDescription
devicesObjectMap of device name to boolean (true = enabled, false = disabled)
portsObjectMap of JACK port name to boolean (true = armed, false = disarmed)
Note: If a device or port is not listed in the config, it defaults to true (enabled/armed).

How the Web Remote Works

The web remote is a Python HTTP server (web_remote.py) that runs on port 8080. It serves a single-page HTML interface and provides REST-like endpoints for control.

HTTP Server

Built on Python's http.server.ThreadingHTTPServer. Listens on 0.0.0.0:8080.

Endpoints

EndpointMethodDescription
/GETServes the web remote HTML interface
/statusGETReturns JSON: recording state, JACK ready, device name
/channelsGETReturns JSON: available JACK capture ports grouped by device, plus current config
/channelsPOSTSaves channel/device arming config to channels.json
/levelsGETReturns JSON: live peak levels (dBFS) for all capture ports
/filesGETReturns JSON: list of WAV files in /media/usb0/ with sizes
/download/<filename>GETDownloads individual WAV file
/download-allGETDownloads all WAVs as a timestamped ZIP archive
/recPOSTStarts recording (runs rec script)
/stopPOSTStops recording (sends SIGTERM to jack_capture)
/del_lastPOSTDeletes the most recent recording
/rescanPOSTRe-scans USB audio devices (runs start_jack)
/delete/<filename>POSTDeletes individual WAV file

How JACK is Configured

JACK (Jack Audio Connection Kit) is the audio server that manages all audio I/O. ChameleonRecorder configures it automatically via start_jack.

Configuration

ParameterValueDescription
Sample rate48000 Hz (fallback: 44100 Hz)48 kHz is preferred; if it fails, 44.1 kHz is tried
Buffer size (period)2048 framesBalances latency vs. stability
Periods (nperiods)3Number of buffers
DriveralsaUses ALSA for USB audio interface communication

Master device selection

On boot, start_jack scans all USB audio cards via /proc/asound/cards and sorts them by capture channel count (descending). The card with the most channels becomes the JACK master. Additional interfaces are bound via alsa_in.

Multi-device setup

# Primary JACK server (largest interface)
jackd -dalsa -dhw:1 -r48000 -p2048 -n3

# Additional interfaces via alsa_in
alsa_in -j "USB_2" -dhw:2 -r48000 -p2048 -n3

How ADAT Clock Sync Detection Works

For Behringer UMC1820 interfaces, ChameleonRecorder automatically detects valid ADAT clock signals and switches to external clock sync.

Detection process

  1. start_jack checks if the card has the UMC1820 Clock Selector Clock Source control (via amixer)
  2. If found, it reads the Optical In ADAT/SMUX Validity control
  3. If the value is on (valid ADAT signal present), it sets the clock source to 2 (external ADAT)
  4. If the value is not on (no valid signal), it sets the clock source to 0 (internal)

Commands used

# Check if UMC1820 is present
amixer -c 1 controls | grep "UMC1820 Clock Selector Clock Source"

# Read ADAT validity
amixer -c 1 cget name='Optical In ADAT/SMUX Validity'

# Set clock source to external ADAT
amixer -c 1 cset name='UMC1820 Clock Selector Clock Source' 2

# Set clock source to internal
amixer -c 1 cset name='UMC1820 Clock Selector Clock Source' 0
Note: This detection runs automatically on boot and when pressing Re-Scan USB Audio Device on the web remote.

How the Fallback Hotspot Works

If no known Wi-Fi network is found within 25 seconds of boot, ChameleonRecorder automatically creates a Wi-Fi access point.

Process

  1. A systemd service (wifi-fallback.service) runs /usr/local/bin/wifi-fallback.sh on boot
  2. The script waits 25 seconds for a Wi-Fi connection
  3. If wlan0 has no IP address (not connected), it creates a hotspot
  4. The hotspot SSID is ChameleonRecorder with password chameleon123
  5. The web remote is accessible at http://10.42.0.1:8080

Configuration

# wifi-fallback.sh (simplified)
sleep 25
if ! ip -4 addr show wlan0 | grep -q "inet "; then
    nmcli device wifi hotspot ifname wlan0 \
        con-name ChameleonHotspot \
        ssid "ChameleonRecorder" \
        password "chameleon123"
fi
Tip: If the Pi is connected to a known Wi-Fi network, the hotspot will NOT activate. This is by design — the Pi prefers your home/studio Wi-Fi.

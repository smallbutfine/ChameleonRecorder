Arquivos de Configuração

channels.json

Localizado em /home/recorder/bin/channels.json. Armazena configurações de armamento por dispositivo e por canal para o controle remoto web.

Formato

{
  "devices": {
    "system": true,
    "USB_2": false
  },
  "ports": {
    "system:capture_1": true,
    "system:capture_2": false,
    "USB_2:capture_1": true
  }
}
ChaveTipoDescrição
devicesObjetoMapa de nome de dispositivo para booleano (true = ativado, false = desativado)
portsObjetoMapa de nome de porta JACK para booleano (true = armado, false = desarmado)
Nota: Se um dispositivo ou porta não estiver listado na config, o padrão é true (ativado/armado).

Como Funciona o Controle Remoto Web

O controle remoto web é um servidor HTTP Python (web_remote.py) que roda na porta 8080. Serve uma interface HTML de página única e fornece endpoints tipo REST para controle.

Servidor HTTP

Construído sobre o http.server.ThreadingHTTPServer do Python. Escuta em 0.0.0.0:8080.

Endpoints

EndpointMétodoDescrição
/GETServe a interface HTML do controle remoto web
/statusGETRetorna JSON: estado da gravação, JACK pronto, nome do dispositivo
/channelsGETRetorna JSON: portas de captura JACK disponíveis agrupadas por dispositivo, mais a config atual
/channelsPOSTSalva a config de armamento de canal/dispositivo em channels.json
/levelsGETRetorna JSON: níveis de pico ao vivo (dBFS) para todas as portas de captura
/filesGETRetorna JSON: lista de arquivos WAV em /media/usb0/ com tamanhos
/download/<filename>GETBaixa arquivo WAV individual
/download-allGETBaixa todos os WAVs como um arquivo ZIP com carimbo de data/hora
/recPOSTInicia gravação (executa o script rec)
/stopPOSTPara gravação (envia SIGTERM para jack_capture)
/del_lastPOSTApaga a gravação mais recente
/rescanPOSTRe-escaneia dispositivos de áudio USB (executa start_jack)
/delete/<filename>POSTApaga arquivo WAV individual

Como o JACK é Configurado

JACK (Jack Audio Connection Kit) é o servidor de áudio que gerencia toda a E/S de áudio. O ChameleonRecorder o configura automaticamente via start_jack.

Configuração

ParâmetroValorDescrição
Taxa de amostragem48000 Hz (fallback: 44100 Hz)48 kHz é preferido; se falhar, 44.1 kHz é tentado
Tamanho do buffer (período)2048 framesEquilibra latência vs. estabilidade
Períodos (nperiods)3Número de buffers
DriveralsaUsa ALSA para comunicação com a interface de áudio USB

Seleção do dispositivo mestre

Na inicialização, start_jack escaneia todas as placas de áudio USB via /proc/asound/cards e as ordena por número de canais de captura (decrescente). A placa com mais canais torna-se o mestre JACK. Interfaces adicionais são vinculadas via alsa_in.

Setup multi-dispositivo

# Servidor JACK primário (interface maior)
jackd -dalsa -dhw:1 -r48000 -p2048 -n3

# Interfaces adicionais via alsa_in
alsa_in -j "USB_2" -dhw:2 -r48000 -p2048 -n3

Como Funciona a Detecção de Sync de Clock ADAT

Para interfaces Behringer UMC1820, o ChameleonRecorder detecta automaticamente sinais de clock ADAT válidos e alterna para sync de clock externo.

Processo de detecção

  1. start_jack verifica se a placa tem o controle UMC1820 Clock Selector Clock Source (via amixer)
  2. Se encontrado, lê o controle Optical In ADAT/SMUX Validity
  3. Se o valor for on (sinal ADAT válido presente), define a fonte de clock como 2 (ADAT externo)
  4. Se o valor não for on (sem sinal válido), define a fonte de clock como 0 (interno)

Comandos usados

# Verificar se UMC1820 está presente
amixer -c 1 controls | grep "UMC1820 Clock Selector Clock Source"

# Ler validade ADAT
amixer -c 1 cget name='Optical In ADAT/SMUX Validity'

# Definir fonte de clock para ADAT externo
amixer -c 1 cset name='UMC1820 Clock Selector Clock Source' 2

# Definir fonte de clock para interno
amixer -c 1 cset name='UMC1820 Clock Selector Clock Source' 0
Nota: Esta detecção roda automaticamente na inicialização e ao pressionar Re-Scan USB Audio Device no controle remoto web.

Como Funciona o Hotspot de Fallback

Se nenhuma rede Wi-Fi conhecida for encontrada em 25 segundos após a inicialização, o ChameleonRecorder cria automaticamente um ponto de acesso Wi-Fi.

Processo

  1. Um serviço systemd (wifi-fallback.service) executa /usr/local/bin/wifi-fallback.sh na inicialização
  2. O script aguarda 25 segundos por uma conexão Wi-Fi
  3. Se wlan0 não tiver endereço IP (não conectado), cria um hotspot
  4. O SSID do hotspot é ChameleonRecorder com senha chameleon123
  5. O controle remoto web é acessível em http://10.42.0.1:8080

Configuração

# wifi-fallback.sh (simplificado)
sleep 25
if ! ip -4 addr show wlan0 | grep -q "inet "; then
    nmcli device wifi hotspot ifname wlan0 \
        con-name ChameleonHotspot \
        ssid "ChameleonRecorder" \
        password "chameleon123"
fi
Dica: Se o Pi estiver conectado a uma rede Wi-Fi conhecida, o hotspot NÃO será ativado. Isso é por design — o Pi prefere seu Wi-Fi de casa/estúdio.

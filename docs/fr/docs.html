Fichiers de Configuration

channels.json

Situé à /home/recorder/bin/channels.json. Stocke les paramètres d'armement par dispositif et par canal pour la télécommande web.

Format

{
  "devices": {
    "system": true,
    "USB_2": false
  },
  "ports": {
    "system:capture_1": true,
    "system:capture_2": false,
    "USB_2:capture_1": true
  }
}
CléTypeDescription
devicesObjetMap de nom de dispositif vers booléen (true = activé, false = désactivé)
portsObjetMap de nom de port JACK vers booléen (true = armé, false = désarmé)
Note : Si un dispositif ou un port n'est pas listé dans la config, il vaut par défaut true (activé/armé).

Comment Fonctionne la Télécommande Web

La télécommande web est un serveur HTTP Python (web_remote.py) qui tourne sur le port 8080. Elle sert une interface HTML à page unique et fournit des endpoints de type REST pour le contrôle.

Serveur HTTP

Construit sur http.server.ThreadingHTTPServer de Python. Écoute sur 0.0.0.0:8080.

Endpoints

EndpointMéthodeDescription
/GETSert l'interface HTML de la télécommande web
/statusGETRetourne JSON : état d'enregistrement, JACK prêt, nom du dispositif
/channelsGETRetourne JSON : ports de capture JACK disponibles groupés par dispositif, plus la config actuelle
/channelsPOSTSauve la config d'armement canal/dispositif dans channels.json
/levelsGETRetourne JSON : niveaux de crête en direct (dBFS) pour tous les ports de capture
/filesGETRetourne JSON : liste des fichiers WAV dans /media/usb0/ avec tailles
/download/<filename>GETTélécharge un fichier WAV individuel
/download-allGETTélécharge tous les WAV en archive ZIP horodatée
/recPOSTDémarre l'enregistrement (exécute le script rec)
/stopPOSTArrête l'enregistrement (envoie SIGTERM à jack_capture)
/del_lastPOSTSupprime l'enregistrement le plus récent
/rescanPOSTRe-scanne les périphériques audio USB (exécute start_jack)
/delete/<filename>POSTSupprime un fichier WAV individuel

Comment JACK est Configuré

JACK (Jack Audio Connection Kit) est le serveur audio qui gère toute l'E/S audio. ChameleonRecorder le configure automatiquement via start_jack.

Configuration

ParamètreValeurDescription
Fréquence d'échantillonnage48000 Hz (repli : 44100 Hz)48 kHz est préféré ; s'il échoue, 44.1 kHz est essayé
Taille du tampon (période)2048 framesÉquilibre latence vs. stabilité
Périodes (nperiods)3Nombre de tampons
PilotealsaUtilise ALSA pour la communication avec l'interface audio USB

Sélection du dispositif maître

Au démarrage, start_jack scanne toutes les cartes audio USB via /proc/asound/cards et les trie par nombre de canaux de capture (décroissant). La carte avec le plus de canaux devient le maître JACK. Les interfaces supplémentaires sont liées via alsa_in.

Configuration multi-dispositif

# Serveur JACK primaire (plus grande interface)
jackd -dalsa -dhw:1 -r48000 -p2048 -n3

# Interfaces supplémentaires via alsa_in
alsa_in -j "USB_2" -dhw:2 -r48000 -p2048 -n3

Comment Fonctionne la Détection de Sync d'Horloge ADAT

Pour les interfaces Behringer UMC1820, ChameleonRecorder détecte automatiquement les signaux d'horloge ADAT valides et bascule sur la sync d'horloge externe.

Processus de détection

  1. start_jack vérifie si la carte a le contrôle UMC1820 Clock Selector Clock Source (via amixer)
  2. S'il est trouvé, il lit le contrôle Optical In ADAT/SMUX Validity
  3. Si la valeur est on (signal ADAT valide présent), il règle la source d'horloge sur 2 (ADAT externe)
  4. Si la valeur n'est pas on (pas de signal valide), il règle la source d'horloge sur 0 (interne)

Commandes utilisées

# Vérifier si UMC1820 est présent
amixer -c 1 controls | grep "UMC1820 Clock Selector Clock Source"

# Lire la validité ADAT
amixer -c 1 cget name='Optical In ADAT/SMUX Validity'

# Régler la source d'horloge sur ADAT externe
amixer -c 1 cset name='UMC1820 Clock Selector Clock Source' 2

# Régler la source d'horloge sur interne
amixer -c 1 cset name='UMC1820 Clock Selector Clock Source' 0
Note : Cette détection s'exécute automatiquement au démarrage et en appuyant sur Re-Scan USB Audio Device sur la télécommande web.

Comment Fonctionne le Hotspot de Secours

Si aucun réseau Wi-Fi connu n'est trouvé dans les 25 secondes suivant le démarrage, ChameleonRecorder crée automatiquement un point d'accès Wi-Fi.

Processus

  1. Un service systemd (wifi-fallback.service) exécute /usr/local/bin/wifi-fallback.sh au démarrage
  2. Le script attend 25 secondes une connexion Wi-Fi
  3. Si wlan0 n'a pas d'adresse IP (non connecté), il crée un hotspot
  4. Le SSID du hotspot est ChameleonRecorder avec le mot de passe chameleon123
  5. La télécommande web est accessible à http://10.42.0.1:8080

Configuration

# wifi-fallback.sh (simplifié)
sleep 25
if ! ip -4 addr show wlan0 | grep -q "inet "; then
    nmcli device wifi hotspot ifname wlan0 \
        con-name ChameleonHotspot \
        ssid "ChameleonRecorder" \
        password "chameleon123"
fi
Astuce : Si le Pi est connecté à un réseau Wi-Fi connu, le hotspot ne s'activera PAS. C'est par conception — le Pi préfère votre Wi-Fi maison/studio.

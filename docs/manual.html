What is ChameleonRecorder?

ChameleonRecorder is a headless, plug-and-play multitrack WAV recorder that runs on a Raspberry Pi 4 (64-bit). It automatically detects any class-compliant USB audio interface or digital mixing console, records uncompressed 24-bit multitrack WAV files directly to a USB flash drive, and provides a mobile-friendly web remote control with live level meters.

No laptop. No DAW. No drivers. Just a Raspberry Pi, a USB audio interface, and a USB stick. Power on and record.

Universal USB Audio

Automatically detects class-compliant USB audio interfaces (Behringer UMC1820, UMC204HD, XR18, X32, MOTU AVB, Focusrite, RME, Zoom) at 48 kHz with 44.1 kHz fallback.

Multi-Device Recording

Record multiple USB interfaces simultaneously. The interface with the most channels becomes the JACK master; additional interfaces are bound via alsa_in with drift compensation.

Web Remote Control

Full control from any phone, tablet, or laptop browser on port :8080. Per-device and per-channel arming, live peak meters, file management, and ZIP download.

Fallback Wi-Fi Hotspot

If no known Wi-Fi is found within 25 seconds of boot, ChameleonRecorder creates its own access point (SSID: ChameleonRecorder, Password: chameleon123) at http://10.42.0.1:8080.

ADAT Clock Sync

Automatically detects valid ADAT clock signals on Behringer UMC1820 interfaces and switches them to external ADAT clock sync for sample-accurate multi-unit recording.

GPIO Controls

Optional physical pushbuttons for Record/Stop and Delete Last, plus a status LED. Both buttons held = safe shutdown.

Connecting storage

Plug a USB flash drive or SSD formatted as exFAT or ext4 into one of the blue USB 3.0 ports. It mounts automatically at /media/usb0. ext4 is recommended to avoid the 4 GB file size limit of FAT32.

Connecting audio interfaces

Connect your USB audio interface(s) to the Raspberry Pi and power them on. ChameleonRecorder automatically detects all USB audio devices on boot. The interface with the most channels becomes the JACK master; additional interfaces are bound via alsa_in.

Multi-interface word clock / ADAT sync

For sample-accurate recording with multiple units (e.g., 2x UMC1820 + 2x ADA8200):

  1. Set ADA8200 #1 to MASTER 48 kHz and connect its WORD CLOCK OUT (75ohm BNC) to ADA8200 #2 (SLAVE WC IN)
  2. Connect ADAT OUT of ADA8200 #1 to ADAT IN of UMC1820 #1, and ADAT OUT of ADA8200 #2 to ADAT IN of UMC1820 #2
  3. Set the front-panel OPT I/O button on both UMC1820 units to ADAT
  4. On boot (or when pressing Re-Scan USB Audio Device), the Pi automatically detects the valid ADAT signal and switches both to external ADAT clock sync

Recording format

Recordings are saved as uncompressed 24-bit WAV files at 48 kHz (or 44.1 kHz if 48 kHz fails). Each file is named with a timestamp: YYYYMMDD_HHMMSS.wav. Files are saved directly to the USB flash drive at /media/usb0/.

Tip: Use a USB 3.0 flash drive or SSD for best performance. USB 2.0 drives may drop samples during multitrack recording due to bandwidth limitations.

Clock Sync & Multi-Device Recording

ChameleonRecorder supports recording multiple USB audio interfaces simultaneously. The system automatically handles clock synchronization:

How it works

  1. On boot, startcapiture scans all USB audio cards via /proc/asound/cards
  2. Cards are sorted by capture channel count (descending) — the card with the most channels becomes the JACK master
  3. The primary JACK server starts on the master card at 48 kHz (with 44.1 kHz fallback)
  4. Additional interfaces are bound via alsa_in with adaptive drift compensation
  5. For Behringer UMC1820: if a valid ADAT signal is detected on the optical input, the clock source is automatically switched to external ADAT

ADAT clock sync detection

When a UMC1820 is detected, ChameleonRecorder checks the Optical In ADAT/SMUX Validity control. If the signal is valid, it sets the clock source to 2 (external ADAT). If not, it sets it to 0 (internal). This happens automatically on boot and when pressing Re-Scan USB Audio Device.

Drift compensation

When multiple interfaces run independently (no word clock connection), their sample clocks drift slightly. JACK's alsa_in mechanism provides adaptive drift compensation — it periodically adjusts the resampling ratio to keep all channels in sync. For critical multi-unit setups, use a word clock or ADAT connection for sample-accurate sync.

Troubleshooting

No audio detected

  • Check that your USB audio interface is connected and powered on
  • Verify the interface is class-compliant (no drivers needed)
  • Press Re-Scan USB Audio Device on the web remote
  • SSH into the Pi and run cat /proc/asound/cards to see if the device is detected
  • Try a different USB port (prefer blue USB 3.0 ports)

USB storage not mounting

  • Ensure the USB drive is formatted as exFAT or ext4 (not FAT32 or NTFS)
  • Check that the drive is plugged into a blue USB 3.0 port
  • SSH into the Pi and run lsblk to see if the drive is detected
  • Check dmesg | tail for mount errors
  • Try a different USB drive or reformat it

Wi-Fi hotspot not appearing

  • Wait at least 25 seconds after boot — the hotspot starts after a 25-second delay
  • If the Pi is connected to a known Wi-Fi network, it will NOT create a hotspot (this is by design)
  • Check that the Wi-Fi country code is set correctly (defaults to DE if unset)
  • SSH into the Pi and check systemctl status wifi-fallback.service
  • Manually start the hotspot: sudo nmcli device wifi hotspot ifname wlan0 con-name ChameleonHotspot ssid "ChameleonRecorder" password "chameleon123"

Konfigurationsdateien

channels.json

Platziert unter /home/recorder/bin/channels.json. Speichert geräte- und kanalweise Scharfschalt-Einstellungen für die Web-Fernbedienung.

Format

{
  "devices": {
    "system": true,
    "USB_2": false
  },
  "ports": {
    "system:capture_1": true,
    "system:capture_2": false,
    "USB_2:capture_1": true
  }
}
SchlüsselTypBeschreibung
devicesObjektZuordnung von Gerätename zu Boolean (true = aktiviert, false = deaktiviert)
portsObjektZuordnung von JACK-Port-Name zu Boolean (true = scharfgeschaltet, false = nicht scharfgeschaltet)
Hinweis: Wenn ein Gerät oder Port nicht in der Konfig aufgeführt ist, wird standardmäßig true (aktiviert/scharfgeschaltet) verwendet.

Wie die Web-Fernbedienung funktioniert

Die Web-Fernbedienung ist ein Python-HTTP-Server (web_remote.py), der auf Port 8080 läuft. Sie liefert eine Single-Page-HTML-Oberfläche und bietet REST-ähnliche Endpunkte zur Steuerung.

HTTP-Server

Basiert auf Pythons http.server.ThreadingHTTPServer. Lauscht auf 0.0.0.0:8080.

Endpunkte

EndpunktMethodeBeschreibung
/GETLiefert die Web-Fernbedienungs-HTML-Oberfläche
/statusGETGibt JSON zurück: Aufnahmestatus, JACK bereit, Gerätename
/channelsGETGibt JSON zurück: verfügbare JACK-Capture-Ports nach Gerät gruppiert, plus aktuelle Konfig
/channelsPOSTSpeichert Kanal-/Geräte-Scharfschalt-Konfig in channels.json
/levelsGETGibt JSON zurück: Live-Peak-Pegel (dBFS) für alle Capture-Ports
/filesGETGibt JSON zurück: Liste der WAV-Dateien in /media/usb0/ mit Größen
/download/<filename>GETLädt einzelne WAV-Datei herunter
/download-allGETLädt alle WAVs als zeitgestempeltes ZIP-Archiv herunter
/recPOSTStartet Aufnahme (führt rec-Skript aus)
/stopPOSTStoppt Aufnahme (sendet SIGTERM an jack_capture)
/del_lastPOSTLöscht die letzte Aufnahme
/rescanPOSTScannt USB-Audiogeräte neu (führt start_jack aus)
/delete/<filename>POSTLöscht einzelne WAV-Datei

Wie JACK konfiguriert ist

JACK (Jack Audio Connection Kit) ist der Audio-Server, der alle Audio-I/O verwaltet. ChameleonRecorder konfiguriert ihn automatisch über start_jack.

Konfiguration

ParameterWertBeschreibung
Sample-Rate48000 Hz (Fallback: 44100 Hz)48 kHz wird bevorzugt; wenn es fehlschlägt, wird 44.1 kHz versucht
Puffergröße (Periode)2048 FramesBalanciert Latenz vs. Stabilität
Perioden (nperiods)3Anzahl der Puffer
TreiberalsaVerwendet ALSA für USB-Audio-Interface-Kommunikation

Master-Geräteauswahl

Beim Boot scannt start_jack alle USB-Audiokarten über /proc/asound/cards und sortiert sie nach Anzahl der Capture-Kanäle (absteigend). Die Karte mit den meisten Kanälen wird der JACK-Master. Zusätzliche Interfaces werden über alsa_in gebunden.

Multi-Device-Setup

# Primärer JACK-Server (größtes Interface)
jackd -dalsa -dhw:1 -r48000 -p2048 -n3

# Zusätzliche Interfaces über alsa_in
alsa_in -j "USB_2" -dhw:2 -r48000 -p2048 -n3

Wie die ADAT-Clock-Sync-Erkennung funktioniert

Für Behringer UMC1820-Interfaces erkennt ChameleonRecorder automatisch gültige ADAT-Clock-Signale und wechselt zur externen Clock-Synchronisation.

Erkennungsprozess

  1. start_jack prüft, ob die Karte die UMC1820 Clock Selector Clock Source-Steuerung hat (via amixer)
  2. Wenn gefunden, liest es die Optical In ADAT/SMUX Validity-Steuerung
  3. Wenn der Wert on ist (gültiges ADAT-Signal vorhanden), setzt es die Clock-Quelle auf 2 (externer ADAT)
  4. Wenn der Wert nicht on ist (kein gültiges Signal), setzt es die Clock-Quelle auf 0 (intern)

Verwendete Befehle

# Prüfen, ob UMC1820 vorhanden ist
amixer -c 1 controls | grep "UMC1820 Clock Selector Clock Source"

# ADAT-Gültigkeit lesen
amixer -c 1 cget name='Optical In ADAT/SMUX Validity'

# Clock-Quelle auf externen ADAT setzen
amixer -c 1 cset name='UMC1820 Clock Selector Clock Source' 2

# Clock-Quelle auf intern setzen
amixer -c 1 cset name='UMC1820 Clock Selector Clock Source' 0
Hinweis: Diese Erkennung läuft automatisch beim Boot und beim Drücken von Re-Scan USB Audio Device auf der Web-Fernbedienung.

Wie der Fallback-Hotspot funktioniert

Wenn innerhalb von 25 Sekunden nach dem Boot kein bekanntes WLAN-Netzwerk gefunden wird, erstellt ChameleonRecorder automatisch einen WLAN-Access-Point.

Prozess

  1. Ein systemd-Dienst (wifi-fallback.service) führt /usr/local/bin/wifi-fallback.sh beim Boot aus
  2. Das Skript wartet 25 Sekunden auf eine WLAN-Verbindung
  3. Wenn wlan0 keine IP-Adresse hat (nicht verbunden), erstellt es einen Hotspot
  4. Die Hotspot-SSID ist ChameleonRecorder mit Passwort chameleon123
  5. Die Web-Fernbedienung ist erreichbar unter http://10.42.0.1:8080

Konfiguration

# wifi-fallback.sh (vereinfacht)
sleep 25
if ! ip -4 addr show wlan0 | grep -q "inet "; then
    nmcli device wifi hotspot ifname wlan0 \
        con-name ChameleonHotspot \
        ssid "ChameleonRecorder" \
        password "chameleon123"
fi
Tipp: Wenn der Pi mit einem bekannten WLAN-Netzwerk verbunden ist, wird der Hotspot NICHT aktiviert. Das ist so gewollt — der Pi bevorzugt dein WLAN zu Hause/Studio.
